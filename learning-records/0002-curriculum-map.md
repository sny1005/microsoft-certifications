# Curriculum map: the exam tests decision frameworks, not product trivia

Read all ~80 content units of the official learning path. The dominant, repeated pattern across modules: nearly every unit reduces to a **selection judgment** — SaaS-first ladder, NLU vs CLU vs generative orchestration, build/buy/extend, single vs multi-agent, which Foundry tool, which monitoring signal → which tuning lever. Lessons should train judgment under scenario phrasing, not recall of feature lists.

**Implications (per-module exam-critical core, used to sequence lessons):**

1. Intro — architect role, OOB agent resources (thin; fold into others)
2. Analyze requirements — agent value assessment; 5 grounding-data dimensions; AI-ready data estate
3. AI strategy — CAF adoption ↔ agent lifecycle map; SaaS-first ladder; single vs multi-agent triggers; knowledge-source limits; build-vs-extend matrix; custom model/SLM criteria; prompt library; AI CoE elements; business roles
4. Costs — ROI categories + 5-driver TCO; ROI model math; build/buy/extend flow; model router rules
5. Design agents — RAI tenets; D365 business terms/customization/connectors; task vs autonomous vs prompt agents; Foundry tool categories; topics+fallback; grounding pipeline (chunk/hybrid/index); Power Apps generative pages + agent feed; PP WAF; NLU/CLU/generative; agent flows; prompt actions
6. Extensibility — Foundry custom models; M365 Agent Builder; 4 extensibility layers; MCP; Computer Use; deep reasoning + voice; Teams/SharePoint agents
7. Orchestrate prebuilt — D365 CS agent types (Agent hub, Intent/Case/KM/Quality agents); M365 agent proposal framework + readiness checklist; Copilot for Sales/Service config; AI hub/AI Builder; F&O plugins + knowledge-source process; sidecar/embedded/outside
8. Monitor/tune — monitoring stack (Azure Monitor, M365 admin, PPAC, Foundry observability); backlog categorization; signal→cause→tuning map; drift
9. Testing — test plan structure; metric set; validation criteria table; prompt validation lifecycle; E2E multi-app scenarios; Copilot-generated test cases
10. ALM — AI data ALM (red/gold, gates A–G, residency); Copilot Studio managed solutions; Foundry agent ALM; custom model ALM; D365 F&O + CX ALM
11. Responsible AI — agent security (managed identity, RBAC, DLP, red team); governance model; model security; prompt manipulation vulns; RAI review; residency validation; grounding access controls; audit trails (Foundry control plane, tracing fields)
